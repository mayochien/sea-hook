## 專案簡介

Sea Hook（大海上鉤）是一個結合即時海況與互動遊戲的台灣海域探索網站。串接中央氣象署的浪高與潮汐開放資料，把海況資訊轉換成互動地圖與圖表，並設計一個依真實浪況調整難度的海釣互動小遊戲，加上魚種圖鑑與知識測驗，讓使用者能一邊玩、一邊認識台灣沿海的漁業與海況資訊。

[Live Demo 線上展示](https://sea-hook.vercel.app/)

## 名稱由來

「大海上鉤」同時結合了海釣情境與 React Hooks 的概念。「Hook」在 React 中是讓元件接入狀態、生命週期與其他功能的機制；在釣魚情境中，則代表魚兒上鉤。這個專案透過 React Hooks、Zustand 與 API 資料串接，將海況、潮汐、遊戲互動與魚種資訊連結在一起，因此取名為「大海上鉤」。

在實作上，`useState` 負責管理遊戲狀態與使用者互動，`useEffect` 處理 API 請求、計時器與咬鉤事件，`useMemo` 則整理魚種與潮汐圖表資料；這些 Hooks 就像把不同功能「鉤」進元件中，讓名稱也對應到專案的技術設計。

## 主要資料來源

- [中央氣象署開放資料平台](https://opendata.cwa.gov.tw/index)：浪高觀測（O-B0075-001）與潮汐預報（F-A0021-001），為海況地圖與潮汐圖表的資料來源。
- [臺灣魚類資料庫](https://fishdb.sinica.edu.tw/) 與 [臺灣海鮮選擇指南](https://fishdb.sinica.edu.tw/seafoodguide/)：魚種圖鑑與知識測驗的資料來源。

## 前端核心技術

### React 19 + TypeScript

使用 React 建立畫面與互動邏輯，並把畫面拆成可重複使用的元件，例如海況地圖、潮汐面板、海釣遊戲、魚種圖鑑與測驗卡片。搭配 TypeScript 定義海況資料、魚種資料與遊戲狀態的型別，讓資料格式更清楚，並在開發階段提早抓出型別錯誤。

### Zustand 狀態管理

使用 [Zustand](https://github.com/pmndrs/zustand) 建立一個集中管理海況 dashboard 狀態的 store（`useSeaConditionStore`），統一管理 `dashboard`、`loading`、`fetchError`、`selectedRegion` 等狀態，並提供 `loadDashboard`、`setSelectedRegion` 兩個 action。海況地圖、潮汐面板、海釣遊戲等元件都透過 selector 訂閱自己需要的狀態片段，取代原本一層層往下傳遞 props 的作法，降低元件間的耦合。

其中最主要的狀態是使用者目前選擇的海域。使用者在海況地圖點選區域後，`setSelectedRegion` 會更新 store；潮汐詳情區塊會依這個選擇顯示對應的浪高、潮差與潮汐資料，海釣遊戲也會讀取同一個當前海域，將浪況分級套用到遊戲的上鉤與脫鉤機率。這讓地圖、詳細海況資料與遊戲區塊共用同一個選擇結果，不需要由 `App` 逐層傳遞 props。

### Vite

使用 Vite 作為前端開發伺服器與建置工具，提供快速的本機開發回饋、模組熱更新（HMR）與最佳化打包功能。

## API 與資料串接

前端透過 `src/lib/cwa.ts` 呼叫中央氣象署開放資料平台的浪高與潮汐 API，並將回傳資料整理成畫面可直接使用的 `FishingDashboard` 格式：

- **浪高資料**：從多個測站的觀測資料中，依地區篩選出最新一筆觀測值，並依浪高換算成「極小浪／小浪／中浪／大浪／巨浪」等分級。
- **潮汐資料**：依地區抓取當天的滿潮、低潮時間與潮汐曲線資料，供潮汐示意圖繪製使用。
- **容錯設計**：若沒有設定 API 金鑰，或請求失敗、資料不足，會自動退回內建的假資料（`mockRegions`），確保畫面永遠有內容可以呈現，不會因為外部 API 問題而整頁空白。

## 遊戲互動邏輯

海釣小遊戲的核心是一個以真實海況資料驅動的狀態機（`FishingGame.tsx`）：

- 使用 `useEffect` 搭配 `setTimeout` 隨機排程「咬鉤」事件，讓等待時間與咬鉤持續時間都落在隨機區間內，避免遊戲節奏一成不變。
- 起竿當下會依照目前海域的浪況分級（`waveLevel`）決定實際上鉤機率——浪越大，就算咬鉤時機抓對了，魚也更容易脫鉤，讓遊戲難度直接反映真實海況資料，而不只是單純的裝飾動畫。
- 釣獲結果會依海域分別累計統計，並依魚種資料庫隨機挑選釣到的魚種與其說明文字。

## 狀態管理與資料處理

### React Hooks

使用 React 內建 Hooks 管理畫面狀態與生命週期，包括：

- `useState`：管理遊戲進行狀態、目前選取的海域、測驗答題進度等。
- `useEffect`：處理 API 請求、遊戲計時器與定期更新目前時間。
- `useMemo`：依選取海域篩選可釣魚種、計算潮汐圖表座標等，避免不必要的重複運算。

### 元件拆分

海釣遊戲進一步拆成 `FishingIntroOverlay`（開場確認海域）、`FishingScene`（遊戲畫面）、`CatchSummaryPanel`（釣獲結果與統計）等子元件，讓主邏輯元件只專注在狀態管理，畫面各自交給對應的子元件負責。

### Tailwind CSS 4

使用 Tailwind CSS 建立整體版面樣式與響應式設計，支援桌面與行動裝置版面，並維持色彩、間距、字體與元件樣式的一致性。

## 穩定性與錯誤處理

- 海況 API 請求失敗時，畫面會顯示錯誤訊息並退回假資料，維持基本瀏覽與遊戲功能。
- 對外部 API 回應做資料檢查與轉換，避免格式不如預期時直接讓畫面出錯。
- 海域切換時會重置遊戲進行中的狀態（下竿、咬鉤、遊戲結果訊息），避免殘留上一個海域的狀態。

## 測試與品質檢查

使用 Vitest 驗證三個核心範圍：

- **Zustand 狀態管理**：測試海域切換、目前海況 selector，以及 dashboard 載入完成後的狀態更新。
- **海釣遊戲規則**：測試尚未咬鉤時提前起竿、不同浪況的上鉤機率與脫鉤判定。
- **魚種列表互動**：測試初始分頁、魚種搜尋、頁面切換，以及圖片資料來源連結。

遊戲規則被抽成純函式，讓核心邏輯可以在不依賴畫面動畫或瀏覽器操作的情況下獨立驗證。

## 技術總結

本專案結合 React 19、TypeScript、Zustand 與 Tailwind CSS 建立前端海況與遊戲平台，並整合中央氣象署開放資料 API、集中式狀態管理、容錯設計與遊戲互動邏輯，涵蓋資料串接、狀態管理與使用者體驗等面向。
